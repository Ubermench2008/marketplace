# Рядом — первая версия фронтенда

Русскоязычный интерфейс текущего Marketplace API. Исходники находятся в
`src/main/resources/static`: HTML, CSS и JavaScript ES-модули без внешних CDN,
зависимостей и обязательного шага сборки. Интернет для интерфейса не нужен.

## Запуск

### Вместе со Spring

Запустите бэкенд обычным способом (PostgreSQL, переменные окружения JWT и
начального администратора должны быть настроены). Откройте:

```text
http://localhost:8080/
```

Статические файлы и API обслуживаются одним приложением. Для этой версии
используется hash-навигация (`/#/cart`), поэтому обновление страницы не требует
отдельного контроллера для маршрутов фронтенда.

### Отдельный сервер для разработки

Из корня репозитория, при установленном Node.js 20+:

```powershell
node frontend/serve.mjs
```

Откройте `http://127.0.0.1:5173/`. Сервер проксирует `/api/` и `/media/` на
`http://127.0.0.1:8080`, включая Bearer JWT и multipart-запросы. CORS-настройки
не нужны. Сервер слушает только loopback. Остановка — Ctrl+C.

Для другого адреса бэкенда или порта фронтенда задайте переменные в текущем
PowerShell перед запуском:

```powershell
$env:MARKETPLACE_BACKEND_URL = "http://127.0.0.1:8080"
$env:MARKETPLACE_FRONTEND_PORT = "5173"
node frontend/serve.mjs
```

Проверка синтаксиса и локальных импортов без запуска приложения:

```powershell
node frontend/check.mjs
```

## Поддерживаемые сценарии

- Каталог с серверной пагинацией и сортировкой по имени/цене; детали с галереей.
- Отзывы товара с пагинацией: оценка 1–5, необязательный текст, создание,
  редактирование до рассмотрения и удаление своего отзыва. Собственный отзыв
  закреплён первым, выделен рамкой и подписан «Ваша оценка»; статус и причина
  отклонения видны автору. Администратор не оставляет отзывы.
- Регистрация покупателя, вход по телефону/email, выход; меню по ролям JWT.
- Корзина: добавление, количество, удаление позиции, очистка, оформление заказа.
- Заказы покупателя: текущие, история, детали, отмена до доставки.
- Продавец: свои товары, создание с обязательными превью и подробными фото,
  PATCH изменённых полей, замена превью, добавление/удаление фото, изменение
  порядка стрелками или перетаскиванием, модерация, публикация одобренного товара,
  отзыв ожидающей модерации заявки для исправления товара, снятие с продажи, архив.
- Администратор: список, создание, изменение и удаление пользователей,
  просмотр их корзин и заказов, отмена заказа и отметка доставки.
- Модерация товаров: очередь и история по статусу, просмотр сохранённого снимка,
  одобрение и отклонение с причиной, история отозванных заявок.
- Модерация отзывов: раздел «Модерация → Отзывы», очередь и история по статусам,
  оценка и текст, автор, ссылки на товар и аккаунт, одобрение с автоматической
  публикацией и отклонение с обязательной причиной. После конфликта версии
  решение блокируется до обновления заявки и повторного просмотра отзыва.
- Мобильная вёрстка, загрузка, пустые состояния, ошибки, подтверждение опасных
  действий, сообщения о завершении операций.

## Границы текущего бэкенда

- Кнопка «Отозвать и вернуться к редактированию» вызывает
  `POST /api/products/{productId}/moderation-requests/cancel` и возвращает `204`.
  Действие доступно владельцу с ролью SELLER только при наличии заявки PENDING.
  Заявка получает CANCELLED, товар — NOT_SUBMITTED; снимок остаётся неизменным,
  `reviewedAt` и модератор не заполняются. Рассмотренную заявку отозвать нельзя.
  Перед использованием нужна миграция V3: она добавляет CANCELLED в ограничение
  таблицы заявок и делает уникальный индекс только по PENDING-заявкам.
- Публикация выполняется продавцом отдельно от одобрения: кнопка
  «Выставить на продажу» вызывает `PATCH /api/products/{productId}/publish`.
  Допускается только свой товар со статусами `OFF` и `APPROVED`; успешный
  ответ — `204 No Content`, новый статус — `ACTIVE`. API восстановления
  из архива пока нет.
- Публичный каталог на сервере пока возвращает все статусы. Интерфейс честно
  показывает их и не позволяет добавить недоступный товар в корзину. Это
  ограничение UI, не замена серверной проверки статуса при покупке.
- Поля `previewImageUrl`, `status` и `moderationStatus` добавлены в
  `ProductDetailsResponse` для превью и корректных состояний просмотра и редактирования. Правила сервисов
  не изменены. Старые клиенты могут игнорировать эти дополнительные поля.
- Поиска по всем товарам/пользователям на сервере нет. Локальный поиск по
  одной странице не маскируется под полноценный поиск.
- Нет API профиля `/me`, смены своего пароля, восстановления пароля,
  refresh-токена, платежей, адресов и реальной доставки. Эти сценарии не
  имитируются. Регистрация создаёт BUYER; аккаунт продавца создаёт администратор.
- Заказ содержит productId и зафиксированную цену, но не название: в истории
  показывается короткий идентификатор товара. Текущая цена товара не подменяет
  цену заказа.
- Изменения полей/фото выполняются несколькими запросами и не являются общей
  транзакцией. При ошибке возможен частичный успех. После сетевой ошибки
  редактор предлагает сверить данные с сервером, не повторяя загрузку вслепую.
- После смены ролей через админа JWT существующей сессии сохраняет старые
  роли до повторного входа/истечения. Фронтенд не выдаёт это за мгновенное
  изменение прав.

## Авторизация и безопасность

JWT хранится в `sessionStorage` только на время вкладки, не в URL или логах.
Это компромисс первого клиента: токен доступен JavaScript; до продакшена стоит
отдельно спроектировать HttpOnly-cookie/refresh и CSRF-модель. Пароли не
сохраняются. При истечении токена нужен повторный вход.

Роли из payload используются только для интерфейса. Авторитетная проверка
подписи, владельца товара и прав остаётся на сервере. HTML из пользовательских
полей экранируется; изображения API принимаются только из `/media/`.

## Структура

- `api.js` — HTTP, ошибки, сессия JWT, адаптация ответа Page.
- `ui.js` — общие компоненты и форматирование.
- `app.js` — навигация и меню ролей.
- `storefront.js` — каталог, авторизация, корзина, заказы.
- `reviews.js` — отзывы на странице товара и управление своей оценкой.
- `seller.js` — кабинет и редактор продавца.
- `admin.js` — пользователи и модерация.
- `admin-reviews.js` — очередь, история и рассмотрение отзывов администратором.
- `styles.css` — дизайн и адаптивная вёрстка.

При росте интерфейса эти независимые модули можно перенести на компонентный
фреймворк; сейчас клиент не добавляет менеджер пакетов и сборщик к Java-проекту.

## Проверка первой версии

Синтаксис ES-модулей и Java-компиляция проверены. В браузере проверены
десктопная/мобильная вёрстка, формы и недоступность настоящего API. Основные
переходы кабинетов, корзины, заказа и модерации дополнительно проверены на
временных ответах API в памяти, не связанных с PostgreSQL. Это не проверка
интеграции с реальным Spring-приложением: его на этой итерации не запускали.
Временный сервер и его данные не входят в исходники.

### Проверка отзывов

Миграции V3–V5 применены к локальному PostgreSQL. Реальный Spring API возвращает
два добавленных тестовых отзыва существующего товара. Сервисные операции
проверены на PostgreSQL в транзакции с откатом: права автора, запрет изменения
рассмотренного отзыва, удаление, сохранение истории, повторное создание,
редактирование ожидающего отзыва, очистка текста, проверка версии и отмена заявки.
Удаление мягкое (`deleted_at`); уникальность товара и автора действует только
для неудалённых отзывов. Ожидающая заявка при удалении получает `CANCELLED`.

Отображение реальных отзывов проверено в браузере с настоящим API. Создание,
редактирование и удаление через интерфейс дополнительно проверены на временных
ответах в памяти, без изменения отзывов существующих пользователей. Это не
сквозной HTTP-тест авторизованных операций. Временные инструменты проверки
удалены; отдельного постоянного набора тестов эта задача не добавляет.

Админский интерфейс модерации отзывов проверен отдельно в браузере на временных
заявках в памяти: переход из модерации товаров, фильтры, просмотр заявки,
одобрение, отклонение с причиной, отменённая заявка и конфликт версии с
блокировкой действий до обновления. Решения отправляют `reviewVersion` из
открытой заявки. Реальные отзывы при этой проверке не изменялись;
сквозная HTTP-проверка с настоящим ADMIN JWT на этой итерации не выполнялась.
