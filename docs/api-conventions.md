# HTTP API

## Ресурсы

Коллекции названы во множественном числе (`/products`, `/orders`), одиночные ресурсы — в единственном (`/cart`, `/reaction`). Товары адресуются публичными UUID. Отзывы товара находятся по `/api/products/{productId}/reviews`, а конкретный отзыв адресуется по `/api/reviews/{reviewId}`.

## Выдача данных

- `GET /api/catalog/products` возвращает одобренные модерацией товары в продаже с положительным остатком. Категория задаётся slug в параметре `category`, диапазон цены — включительными границами `minPrice` и `maxPrice`.
- `GET /api/products/stocks` принимает несколько публичных ID в `productIds` и возвращает массив остатков. Остаток своего товара продавец читает и корректирует через `/api/seller/products/{productId}/stock`.
- Сортировка и пагинация передаются в параметрах запроса. Страницы возвращаются в формате `{content, page}`; пустая выборка возвращается без ошибки.

## Изменение данных

Частичное обновление выполняется через `PATCH`, полная замена — через `PUT`. Например, порядок фотографий заменяется целиком через `PUT /api/products/{productId}/details-images/order`. Публикация товара, решение по модерации и отмена заказа оформлены отдельными командами `POST`.

Создание товара принимает multipart: JSON в части `product`, превью в `previewImage` и фотографии в `detailsImages`. Создание ресурса возвращает `201`, успешное изменение без тела — `204`.

## Доступ и ошибки

Публичный каталог расположен под `/api/catalog`, кабинет продавца — под `/api/seller`, административные операции — под `/api/admin`. Публичный доступ задан в `SecurityConfig`, ограничения по ролям — через `@PreAuthorize`. В операциях над своими товарами и заказами сервер проверяет владельца.

Ошибки возвращаются в формате `ApiErrorResponse` с полями `status`, `message`, `errors`, `timestamp`. Сообщения на английском. Конфликт с текущим состоянием, например нехватка товара при оформлении, возвращает `409`.
